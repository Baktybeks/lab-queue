# Архитектура фронтенда

Приложение использует упрощённую FSD и TanStack Query. Правила очереди и проверка прав остаются в PostgreSQL; функции Supabase и схема базы при этом рефакторинге не менялись.

## Слои

- `src/app`: запуск приложения, QueryClientProvider и глобальные стили.
- `src/pages`: страница входа и общая страница очереди с представлением студента или преподавателя. Компоновка ролей общая, поскольку большая часть интерфейса совпадает.
- `src/widgets`: очередь, шапка, навигация, управление сессией и личная история.
- `src/features`: вход, команды очереди, создание преподавателей, создание и импорт студентов, редактирование имени.
- `src/entities`: типы очереди и её снимок, данные студентов, представление сессии и медалей.
- `src/shared`: клиент Supabase, настройки Query Client, ключи кеша и общий вызов Edge Functions.

Импорты направлены вниз по слоям; это проверяется тестом. На этом этапе связанные сущности используют общие типы агрегата очереди, без искусственного дублирования интерфейсов.

## Серверное состояние

Очередь имеет ключ `['queue', userId, sessionId]`; личная история — `['student-history', userId]`; список студентов — `['students', userId]`. Кеш хранится только в памяти. При выходе или смене аккаунта кеш очищается, незавершённые запросы отменяются. При переключении сессии разрешена временная копия прежней очереди того же пользователя; кнопки действий заблокированы до получения выбранной сессии.

Очередь обновляется каждые 5 секунд, без опроса скрытой вкладки. При возврате фокуса и восстановлении сети выполняется фоновое обновление. Старые данные остаются на экране. Повторный SIGNED_IN того же аккаунта не очищает кабинет. Supabase Auth продолжает хранить токены в localStorage и обновлять их автоматически.

Команды выполняются через `useMutation`. Автоматический повтор команд отключён, чтобы после неопределённого сетевого ответа не отправить «Следующий» или выдачу допзадания повторно. После успешного действия инвалидируются очередь и личная история. Создание/переименование студента обновляет список аккаунтов и очередь. Поля форм, раскрытие аккордеонов и ход JSON-импорта — локальное состояние интерфейса.

## Проверки

`npm test` проверяет правила БД, права, очередь и кеш (разделение аккаунтов/сессий, объединение одинаковых запросов, отмена при очистке). `npm run build` проверяет TypeScript и собирает сайт. React, Query и Supabase выделены в отдельные файлы сборки. Публикация по-прежнему идёт через GitHub Pages.
